# Docs 语言与版本闭环

## Goal

交付文档集级语言注册、版本族关联、文档集派生、语言派生和前台语言/版本切换；切换优先保持当前逻辑文档，缺失内容时提供
明确、可预测的回退，不引入 Git 分支或翻译平台。

## Status

Open

## Current

2026-08-28 补齐两个管理断点：单个文档集现在可以先设置不可变 `x.y.z` 并建立只有一个成员的版本族，不必为了获得版本号先
克隆第二个集合；语言管理新增 Locale Derivation，从已有语言复制完整文档树到新目标语言，目标文档使用新 ID、保留
`translationKey`/层级/slug/Badge 并统一为草稿，目标语言已有任何文档时拒绝覆盖。目标语言不存在时由同一事务注册，失败不留
空语言。

2026-08-28 根据 Python 等独立版本文档入口的成熟做法，将旧“单个文档集内多 Version 行”调整为“版本族关联多个独立文档集”。
新增 0016 迁移、不可变 `major.minor.patch`、文档集派生事务、关联版本 API 与前台跨集合切换；派生会复制语言、文档树、
翻译关联键与视觉元数据，目标文档统一为草稿。原 `collection_versions/default` 暂作为不可见存储分区保留，避免同时重写搜索、
评论、导入和 URL 生命周期。文档 Badge 也已贯通 API、编辑器、目录、公开标题和管理列表。

本轮遵照用户要求未操作任何服务进程或运行数据库迁移。临时 Go Workspace 下 catalog/dao/controller/api 测试通过，Web
typecheck、相关源码合同及 Playwright 用例解析通过；全量 Node 单测仍有与本 Work 无关的旧 Asset/源码断言待清理。真实浏览器
派生验收需在下一次正常迁移和服务启动窗口执行。

## Next

下一次正常迁移窗口执行 0016 后，运行“文档集语言与版本保持同一逻辑页面上下文”和文档集管理两条 Playwright，确认首次补
源版本号、派生草稿、版本族 SemVer 排序、跨集合语言回退和 Badge 展示，再移除已无调用者的旧 Version 管理 HTTP 表面。

## Progress

- 文档集管理列表拆分为合法的数据行与独立操作区，提供公开跳转和编辑按钮。
- 调研确认语言应属于文档集、版本 key 应稳定、`translationKey` 应作为跨语言/版本的逻辑页面身份。
- `0015_collection_locales` 已在本地数据库执行并保持 checksum；新建文档集自动获得 English 默认语言，导入包可注册新增语言。
- 版本产品模型已从内部 Version 行迁移到版本族关联的独立文档集；公开 URL 不再使用 version query。
- 文档编辑器、后台列表、目录与公开链接均以文档集默认语言为准，不再把 English 写死为所有文档集的默认筛选。
- Document Badge 只表达轻量阅读提示，不承担发布状态、版本或权限语义。
