# Context

## Product decisions

- 版本能力保留，但目标模型改为“一个文档集一个版本，多个文档集组成版本族”；现有文档集内 Version 模型属于待迁移实现。
- 新版本通过文档集派生创建，派生后独立维护；不做 Git 分支、实时继承或自动发布流水线。
- 语言由文档集注册，不使用全站固定枚举；后台提供常用预设并允许合法 BCP 47 自定义语言。
- 新语言可从同一文档集的已有语言派生完整草稿树；目标语言必须已启用且尚无文档，派生保留 `translationKey`、slug、层级和
  内容，所有目标文档统一为草稿，避免覆盖部分翻译。
- 文档语义版本固定使用不可变 `major.minor.patch`；locale code 同样保持稳定。
- `translationKey` 是跨语言、跨版本族成员的逻辑文档身份；标题、slug 与父级可因语言和集合不同。
- 语言继续使用 query；版本切换改为跳转目标文档集的独立路径，不再使用 version query。

## Switching behavior

- 语言切换优先解析目标语言、当前版本、同一逻辑文档；缺失时显示默认语言同页并明确提示，再回退到目标上下文首页。
- 版本切换优先解析目标版本化文档集、当前语言和同一逻辑文档；缺失时回退目标文档集首页。
- 默认语言省略 query；版本族只有一个成员时不显示版本选择器。
- 每个文档集只承载自己的语言变体，不创建“内部版本 × 语言”笛卡尔积。
